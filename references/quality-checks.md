# 质量控制、修改边界与验收案例

## 交付检查

| 检查项 | 通过条件 | 不通过时处理 |
|---|---|---|
| 车型与来源 | 型号、年款、市场、配置和工况一致，关键技术有来源 | 查证、区分或删掉 |
| 政策 | 时间、地区、版本、用户/门店口径明确 | 加必要条件，不发明 |
| 具体性 | 关键卖点落到事实与场景 | 换成已确认的购买理由 |
| 表达 | 自然聊天或专业口播，无配置流水账、夸张空话 | 重写句子，保留事实 |
| 安全与广告 | 不把辅助驾驶当无人驾驶；不承诺零风险、绝对性能或无根据最优/最低 | 删掉或改为有证据的限定表述 |
| CTA | 仅在符合用户需求时使用，无擅自加引流 | 删除或按指定渠道改写 |
| 批次 | 数量正确，角度或场景实质不同，独立可用 | 只修未通过条目 |
| 字数/时长 | 按用户规定的口径；时长为合理估算 | 缩短/重写并再次检查 |
| 分镜 | 秒数连续、镜头数准确、台词和动作匹配、可拍摄 | 调整台词/镜头而非硬切 |
| 输出范围 | 只输出所需类型，无无关图像或报告 | 去掉多余栏目 |

特别注意：不要凭车型宣传图推断未证实的功能；驾驶辅助识别、接管、泊车能力应保持真实操作前提，避免“兜底”“绝不会撞”“可以不用管”这种保证。法律和地方广告规范可能变化，不能宣称已完成法务审核；如涉具体合规要求，可依据有效官方规定核查。

## 精确字数

如有 Python 环境，将各条正文写入 JSON 数组（每项为字符串），运行：

```bash
python scripts/count_copy.py copies.json --target 80 --equal
```

`--include-punctuation` 改为统计除空白外全部字符；`--equal` 检查条目等长。检查不通过时只改正文，再核验。字数统计是字符统计，不等同朗读速度，数字与英文字母逐字符计数。不要自动去掉正文标点或改动口语节奏，只在统计时排除标点。脚本未运行时不要宣称机械计数通过。

## 验收案例（用于使用后迭代；不是声称已实测）

1. 输入：“某品牌某车型，写5条20秒口播。”预期：先验证车型，5条不同核心角度；明确必要的版本及事实来源，不凭空加价格或 CTA。
2. 输入：“商用车，10条，每条80字，只给这些政策素材，不要直播间引导。”预期：仅采用提供的优惠口径，10条无 CTA，正文严格等长，并报告统计口径（除非用户只要正文）。
3. 输入：“把这段口播做成30秒、5个镜头，主播坐车内，给画面、机位、台词和字幕，不要图片。”预期：5镜时间连续到30秒，主播车内为主，少量合理B-roll，输出表格，不生成图像。
4. 输入：“改成妈妈和小孩的对话，自动泊车自然收尾。”预期：口语化对白、自然动作、真实功能限制，无硬促销及不安全演示。
5. 输入：“最新款最低价多少？写紧急清库文案。”预期：独立查价格、版本和活动；无可靠清库信息不编造，不写虚假稀缺；用户提供政策时标注来源和限制。
6. 输入：“其他文案不动，只把第二条换一种切入角度。”预期：保留已核验的事实基础和其他条目，返回修订的第二条，除非用户要整批。
7. 输入：“不要联网，按我发的文案改。”预期：不检索、不增加未提供参数，保留原约束，必要时提示事实未独立核验。
